# معماری فنی LUNA AI (نسخه ۱.۰)

## ۱. هدف و فلسفه طراحی
**LUNA AI** به‌گونه‌ای مهندسی شده است که روی سخت‌افزارهای اقتصادی و بدون کارت گرافیک مستقل (**Windows 10، رم 8GB، پردازنده Intel Core i5 نسل سوم، گرافیک مجتمع Intel HD Graphics**) با تکیه بر **Ollama** و مدل بسیار سبک **`qwen3:0.6b` (~522MB)** بالاترین سطح دقت، امنیت، اتوماسیون آفیس/ویندوز و کیفیت پاسخ فارسی را ارائه دهد.

چالش اصلی مدل‌های زیر یک میلیارد پارامتر (`0.6B`) ضعف ذاتی واژگان فارسی و خطای استخراج آرگومان در پرامپت‌های سنگین است. برای غلبه بر این محدودیت بدون مصرف رم اضافی، معماری **چندلایه هیبرید و تقطیر دانش** پیاده‌سازی شده است:

```
پیام کاربر (رابط شیشه‌ای WebSocket / REST)
   │
   ▼
[لایه ۰: تشخیص زبان خودکار + نرمال‌سازی فارسی (ی/ک/ارقام/نیم‌فاصله)]
   │
   ▼
[لایه ۱: مسیریاب آبشاری ۴ مرحله‌ای (core/router.py)]
   ├─ مرحله ۰: دستورات صریح (/calc, /google, /memory, /notepad, /files) + مسدودساز فرمان شِل
   ├─ مرحله ۱: استخراج‌گر قطعی عبارات ریاضی، Word، Excel، Notepad و حافظه تعاملی (< 1ms CPU)
   ├─ مرحله ۲: طبقه‌بند سبک زیرکلمه‌ای char_wb(3..5) TF-IDF (< 2ms CPU، بدون GPU)
   └─ مرحله ۳: مسیریاب JSON مقید به گرامر در Ollama (`format=JSON_SCHEMA`, `think=False`) + تعمیر RFC-8259
   │
   ├──► در صورت نیاز به ابزار حساس (حذف فایل، ذخیره حافظه، فرم وب) ──► [ConfirmationManager] ──► توقف تا تأیید کاربر
   │
   ├──► اجرای ابزارهای Allowlist در [SandboxManager] با Timeout و پشتیبان خودکار (.bak)
   │      ├─ calculator.py   (موتور AST امن بدون eval)
   │      ├─ word_editor.py  (python-docx + پشتیبان خودکار)
   │      ├─ excel_editor.py (openpyxl + فرمول امن + مرتب‌سازی + پشتیبان خودکار)
   │      ├─ notepad.py      (subprocess امن با shell=False روی ویندوز)
   │      ├─ file_manager.py (مسیر canonical، مسدودسازی symlink و ..)
   │      └─ google_search.py / browser.py (Playwright + مرز <untrusted_external_data> + توقف در CAPTCHA)
   │
   ▼
[لایه ۲: بازیابی هیبرید حافظه (memory/retrieval.py)]
   ├─ حافظه کوتاه‌مدت (پنجره لغزان + خلاصه‌سازی تدریجی + حذف بلوک‌های <think>)
   ├─ حافظه بلندمدت SQLite WAL + جدول مجازی FTS5 BM25 + شباهت کسینوسی TF-IDF با ادغام RRF
   └─ حافظه آموزشی Few-Shot (`teacher_exemplars`) برای تقویت پاسخ فارسی مدل کوچک در حالت آفلاین
   │
   ▼
[لایه ۳: تولید پاسخ + اعتبارسنجی خروجی (core/response_validator.py)]
   ├─ پایش تکرار توکن، نشت الفبای بیگانه (سیریلیک/چینی)، برش ناقص جملات و ادعای دروغین اجرای ابزار
   └─ در حالت `hybrid_teacher`: کمک از معلم آنلاین رایگان (بدون کلید پولی، پس از حذف داده‌های حساس) و تقطیر خودکار در SQLite
```

## ۲. تفکیک مرزهای امنیتی
1. **Allowlist ابزارها**: هیچ نام ابزاری خارج از `ToolRegistry` قابل فراخوانی نیست و هیچ دستور شِل مستقیمی از مدل پذیرفته نمی‌شود.
2. **Sandbox مسیر فایل**: تمام مسیرها با `Path.resolve()` کانونیکال شده و لینک‌های نمادین (Symlink) به بیرون از `data/workspace/` یا مسیرهای traversal (`..`, UNC) مسدود می‌شوند.
3. **پشتیبان‌گیری خودکار (`.bak`)**: پیش از هرگونه ویرایش یا بازنویسی فایل‌های موجود در Word، Excel، Notepad، فایل متنی یا `settings.json`، نسخه پشتیبان زمان‌دار در `data/backups/` ایجاد می‌گردد.
4. **حذف اطلاعات حساس (`SecretRedactor`)**: رمزهای عبور، شماره کارت‌های بانکی ۱۶ رقمی، کلیدهای API و توکن‌های Bearer/JWT پیش از ثبت در حافظه بلندمدت، لاگ ممیزی (`logs/luna.log`) یا ارسال به معلم آنلاین مسدود و سانسور می‌شوند.
5. **مرز محتوای غیرمطمئن وب (`PromptInjectionGuard`)**: تمام متون استخراجی از اینترنت درون تگ غیرقابل اجرای `<untrusted_external_data executable="false">` قرار گرفته و دستورات تزریقی (`ignore previous instructions`, `دستورات قبلی را نادیده بگیر`) خنثی می‌شوند.

## ۳. معماری آینده صوتی (مرحله ۱۲)
در `core/voice_interface.py` قراردادهای انتزاعی `STTAdapter` و `TTSAdapter` بدون اشغال رم پیاده‌سازی شده‌اند تا در نسخه‌های بعد، موتورهای سبک CPU مانند `Whisper INT8 ONNX`، `Vosk فارسی` یا `Piper TTS` به‌صورت پلاگین متصل شوند.
